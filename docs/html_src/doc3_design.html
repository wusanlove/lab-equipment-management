2. 项目设计原则简介

2.1 实用性与高内聚低耦合原则

系统设计摒弃过度复杂的冗余框架堆砌，坚持“高内聚、低耦合”的工程实用性原则。每个业务模块仅关注自身核心职责：权限与密码哈希内聚于 AuthService，设备状态迁移内聚于 EquipmentService，借还联动内聚于 BorrowService。层与层之间通过明确的方法签名交互，杜绝跨层直接篡改底层集合数据。

2.2 单一职责原则（SRP）与门面模式（Facade）

严格遵循单一职责原则（Single Responsibility Principle）：领域实体类（domain 包）仅封装业务属性、不变式校验（如单价非负、应还日期不早于借出日期）及状态转换规则；数据访问类（dao 包）仅负责主键生成、集合存储与多条件过滤查询；业务服务类（service 包）负责 RBAC 鉴权、状态流转与审计记录。同时，在控制层引入 GoF 门面模式（Facade Pattern），构建 LabSystemFacade 统一对外暴露业务入口，屏蔽底层 6 个 Service 与 7 个 DAO 之间的复杂装配关系。

2.3 开闭原则（OCP）与依赖倒置原则（DIP）

遵循开闭原则（Open-Closed Principle）与依赖倒置原则（Dependency Inversion Principle）：各业务 Service 通过构造函数依赖注入（Constructor Injection）接收所需的 DAO 与协作 Service 实例（并通过 Objects.requireNonNull 强校验），使得单元测试可独立创建全新的 InMemoryDatabase 实例实现 100% 隔离测试；未来扩展新的设备类别、审批状态或切换底层关系型数据库时，对扩展开放、对核心业务代码修改关闭。

2.4 有限状态机（FSM）防错设计原则

针对实验设备全生命周期流转这一核心难点，采用表驱动/枚举内聚有限状态机（Finite State Machine）设计原则。将合法状态迁移路径内聚在 EquipmentStatus.canTransitionTo(target) 方法中，强制规定 SCRAPPED（已报废）为不可逆吸收终态，规定 BORROWED（已借出）状态严禁越过归还验收直接报废，从架构根源上消除了状态错乱隐患。

3.4 核心接口与关键代码设计

为直观展示系统核心业务规则的代码落地实现，以下精选三段最具代表性的核心源码片段（均严格截取自 src/main/java/cn/edu/ctgu/labms/）。

（1）设备四态有限状态机守卫实现（EquipmentStatus.canTransitionTo）：通过枚举内聚状态转移矩阵，确保任何状态变更请求必须经过合法性判定，特别是保证 SCRAPPED 终态绝不向任何其他状态逆向流转，且 BORROWED 状态不可绕过归还直接报废。关键代码如下：

package cn.edu.ctgu.labms.domain;

// 实验设备全生命周期四态有限状态机枚举（节选自 EquipmentStatus.java）

public enum EquipmentStatus {

    IN_STOCK("在库可用"), BORROWED("已借出"), MAINTENANCE("维修中"), SCRAPPED("已报废");

    private final String displayName;

    EquipmentStatus(String displayName) { this.displayName = displayName; }

    public String getDisplayName() { return displayName; }

    /** 校验从当前状态转移到目标状态是否合法 */

    public boolean canTransitionTo(EquipmentStatus target) {

        if (target == null || this == target) { return false; }

        switch (this) {

            case IN_STOCK:    return target == BORROWED || target == MAINTENANCE || target == SCRAPPED;

            case BORROWED:    return target == IN_STOCK || target == MAINTENANCE;

            case MAINTENANCE: return target == IN_STOCK || target == SCRAPPED;

            case SCRAPPED:    return false; // 已报废为永久终态，严禁逆向流转

            default:          return false;

        }

    }

}

（2）设备归还验收与损坏自动转修跨服务联动实现（BorrowService.returnEquipment）：当归还验收标志 conditionOk == true 时，驱动设备恢复为 IN_STOCK；当 conditionOk == false 时，自动委托 maintenanceScrapService.reportFault() 将设备流转至 MAINTENANCE 并生成维修工单。关键代码如下：

// 归还设备验收：完好恢复在库，受损自动转入维修并生成工单（节选自 BorrowService.java）

public BorrowRecord returnEquipment(String recordId, String operatorId,

                                    LocalDate returnDate, boolean conditionOk, String damageReason) {

    authService.requireRole(operatorId, Role.LAB_MANAGER, Role.ADMIN, Role.TEACHER);

    BorrowRecord record = getRecordOrThrow(recordId);

    if (record.isReturned()) {

        throw new IllegalStateException("归还失败：借用记录[" + recordId + "]已归还，不可重复操作");

    }

    if (returnDate.isBefore(record.getBorrowDate())) {

        throw new IllegalArgumentException("归还日期不能早于借出日期");

    }

    record.setReturnDate(returnDate);

    record.setReturnConditionOk(conditionOk);

    borrowRecordDao.save(record);

    String eqCode = record.getEquipmentCode();

    if (conditionOk) {

        equipmentService.transitionStatus(eqCode, EquipmentStatus.IN_STOCK, operatorId, "借用归还验收完好");

        auditLogDao.append(operatorId, "EQUIPMENT_RETURN_OK", recordId, "设备归还验收完好，已恢复在库");

    } else {

        String faultDesc = (damageReason == null || damageReason.trim().isEmpty())

                ? "借用归还验收发现设备受损，自动转入维修" : "归还验收受损：" + damageReason.trim();

        MaintenanceScrapRecord ticket = maintenanceScrapService.reportFault(eqCode, operatorId, faultDesc);

        auditLogDao.append(operatorId, "EQUIPMENT_RETURN_DAMAGED", recordId, "受损自动生成工单:" + ticket.getRecordId());

    }

    return record;

}

（3）实验耗材防超领校验与安全阈值低水位预警实现（ConsumableService.outboundStock）：在领用出库时强制校验库存充足性（防超领），并在扣减库存后调用 consumable.isLowStock()（判定 currentStock < safetyThreshold）自动触发低水位预警标记。关键代码如下：

// 耗材领用出库：防超领拦截与低库存阈值自动预警（节选自 ConsumableService.java）

public Consumable outboundStock(String operatorId, String code, int quantity, String purpose) {

    authService.getActiveUserOrThrow(operatorId);

    if (quantity <= 0) { throw new IllegalArgumentException("领用出库数量必须大于0"); }

    Consumable consumable = getByCodeOrThrow(code);

    int currentStock = consumable.getCurrentStock();

    if (currentStock < quantity) {

        throw new IllegalStateException(String.format(

                "耗材库存不足：[%s-%s]当前库存为 %d%s，申请领用 %d%s",

                consumable.getCode(), consumable.getName(), currentStock, consumable.getUnit(), quantity, consumable.getUnit()));

    }

    int newStock = currentStock - quantity;

    consumable.setCurrentStock(newStock);

    consumableDao.save(consumable);

    String alertMsg = consumable.isLowStock() // currentStock < safetyThreshold 时返回 true

            ? String.format("【触发低库存预警：当前%d < 阈值%d】", newStock, consumable.getSafetyThreshold()) : "";

    auditLogDao.append(operatorId, "CONSUMABLE_OUTBOUND", code,

            String.format("耗材[%s]领用 -%d%s，余量=%d%s %s", consumable.getName(), quantity, consumable.getUnit(), newStock, consumable.getUnit(), alertMsg));

    return consumable;

}

4.2 核心业务模块交互时序设计

各核心功能模块（CM1～CM7）的详细算法逻辑与跨层交互设计如下：

（1）CM1 安全认证与 RBAC 权限模块：接收注册或登录请求，通过 MessageDigest 计算 256 位哈希值；在所有受保护业务入口处执行 requireRole(userId, allowedRoles...)，若当前用户的角色不在许可列表内，立即记录 PERMISSION_DENIED 审计日志并抛出 SecurityException。

（2）CM2 设备台账与多维检索模块：在 EquipmentDao.search() 中采用流式谓词过滤（Stream Predicate），支持关键字（忽略大小写匹配编码、名称、规格）、分类、状态与存放实验室位置的任意组合检索；当参数为空或 null 时自动视为通配该维度。

（3）CM3 采购审批与到货批量自动入库模块：在 PurchaseService.receiveOrderAndInbound() 中，首先验证申购单状态必须为 OrderStatus.APPROVED（严禁未批或已驳回单据入库），随后按申购单中的数量 order.getQuantity() 执行循环，每次调用 equipmentService.registerEquipment() 自动分配新设备编号（如 EQ-2026-1001～1003），最后将申购单置为 COMPLETED。

（4）CM4 设备借用与受损归还自动转修模块：借出与归还验收涉及跨多个服务层对象的协同交互。设备借用申请、状态校验及归还验收发现故障自动转入维修工单的跨层 UML 时序图如图 4-2 所示。

图 4-2 设备借还与损坏自动转修跨层 UML 时序图

（5）CM5 维修闭环与报废核销模块：completeRepair() 校验维修单处于 PENDING 状态后，驱动设备状态从 MAINTENANCE 恢复为 IN_STOCK；approveScrap() 则在批准报废前自动遍历该设备名下所有未结案的维修单将其同步结案，再将设备状态永久推入 SCRAPPED。

IN_STOCK BORROWED borrowEquipment() 允许 借用人有效、应还日 $\ge$ 借出日，生成借用记录并变更为已借出。
IN_STOCK MAINTENANCE reportFault() 允许 日常巡检发现故障发起报修，生成 PENDING 维修工单。
IN_STOCK SCRAPPED approveScrap() 允许 达到折旧年限经管理员核准直接报废，进入永久终态。
BORROWED IN_STOCK returnEquipment(true) 允许 归还验收完好（conditionOk=true），恢复在库可用状态。
BORROWED MAINTENANCE returnEquipment(false) 允许 归还验收受损（conditionOk=false），自动联动生成维修工单。
BORROWED SCRAPPED approveScrap() 禁止 拦截：抛出 IllegalStateException，未归还设备严禁直接报废（TC16）。
MAINTENANCE IN_STOCK completeRepair() 允许 维修工单完工验收合格，工单置为 COMPLETED，设备恢复在库。
MAINTENANCE SCRAPPED approveScrap() 允许 确认无维修价值批准报废，自动同步结案待修单并锁定终态（TC33）。
SCRAPPED 任意其他状态 transitionStatus() 禁止 终态保护拦截：canTransitionTo() 返回 false，严禁复活或借出（TC15）。
