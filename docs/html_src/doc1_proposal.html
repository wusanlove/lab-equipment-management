1. 项目提出

1.1 项目简介

随着高校新工科建设与科研创新实践的深入推进，高校计算机、电子信息、人工智能及嵌入式工程等专业实验室的仪器设备与实验耗材规模呈指数级增长。以三峡大学计算机与信息学院实验中心为例，各专业实验室日常管理的资产既包含高价值的深度学习图形工作站、数字存储示波器、高精度稳压电源等固定资产设备，又涵盖嵌入式开发实验箱、无铅焊锡丝、贴片电阻包及无水乙醇（危化品）等高频领用的教学物资与耗材。实验设备与耗材的高效流转、完好率保障及合规审计，直接决定着实验教学质量与科研课题进度。

然而，当前众多高校实验室在设备与耗材管理上仍普遍依赖传统的纸质借还登记簿或离散的电子表格（Excel），在实际运维中暴露出四大核心痛点：其一，设备状态与库位黑箱化，设备在“在库可用、已借出、维修中、已报废”多状态间的流转缺乏强状态机约束，极易出现故障设备被重复借出、已报废资产未下账等管理混乱；其二，设备采购与建档入库脱节，教师提交采购申请获批并到货验收后，实验员仍需手工逐台录入设备台账，不仅效率低下且易产生账实不符；其三，借还验收与维修流转断链，师生归还设备时若发生通道损坏或接口故障，缺乏自动化转修闭环机制，导致受损设备无法及时生成维修工单；其四，实验耗材与危化品缺乏动态预警，高频消耗品与危化试剂无法在库存跌破安全水位时自动报警，常因缺货影响实验课开展。

针对上述业务痛点，本项目小组正式提出研发《实验室设备管理系统》（Laboratory Equipment & Consumables Lifecycle Management System，简称 LabMS v1.0）。本系统以“全生命周期状态机强约束”与“跨模块业务自动联动”为核心设计理念，将权限认证、设备台账、申购入库、借还验收、维修报废、仓库盘点与耗材预警融为一体，实现高校实验室资产管理的规范化、数字化与可追溯化。

1.2 项目目标

本项目的总体目标是构建一套架构清晰、状态严密、安全可靠且交互友好的智慧实验室设备与耗材全生命周期管理系统，具体分为以下三个维度的建设目标：

（1）师生便捷服务维度目标：面向全院学生与指导教师提供一站式设备查询与业务申办服务。支持按关键字、设备分类、存放实验室及实时状态进行毫秒级多维组合检索；支持在线发起设备借用申请、归还登记与故障报修；支持指导教师在线提报教学科研新设备申购单及申领实验试剂耗材，消除线下跑签繁琐流程。

（2）实验室精细化管控维度目标：面向实验室管理员与系统管理员构建全流程闭环管控体系。建立基于 RBAC（基于角色的访问控制）的四级权限防线与 SHA-256 密码安全摘要机制；打通“申购审批—到货验收—自动批量生成在库设备台账”自动化链路；建立严密的设备四态有限状态机（IN_STOCK 在库可用、BORROWED 已借出、MAINTENANCE 维修中、SCRAPPED 已报废），实现“受损归还自动流转至维修态并生成维修工单”及“报废终态永久锁定”；实现多实验室盘点完好率自动核算与耗材低库存安全阈值实时预警。

（3）软件工程质量与交付维度目标：严格遵循面向对象 SOLID 设计原则与五层体系架构规范（表现层、控制门面层、业务服务层、数据持久层、领域模型层），保证核心代码零外部脆弱依赖、高内聚低耦合；配套构建 40 项自动化单元测试套件与 36 项系统黑盒测试用例，确保核心业务覆盖率与测试通过率均达到 100%。

1.3 系统边界

为确保项目在既定周期内高质量交付，需明确界定《实验室设备管理系统》的功能范围与外部边界。本系统的总体功能模块划分与业务边界如图 1-1 所示。

图 1-1 系统功能结构图

如图 1-1 所示，系统边界以内的核心业务涵盖七大功能模块（M1～M7）：

（1）安全与权限管理模块（M1）：包含用户注册、SHA-256 密码加密存储、用户登录认证、四角色（系统管理员 ADMIN、实验室管理员 LAB_MANAGER、指导教师 TEACHER、学生 STUDENT）RBAC 权限拦截、账号启用/禁用（含管理员防自锁保护）以及全链路安全审计日志追踪。

（2）设备信息管理模块（M2）：包含实验设备全生命周期档案建档（编码、名称、型号规格、类别、厂商、单价、购置日期、质保期限、存放位置）、质保日期合法性校验、多维条件组合检索、存放库位调拨以及四态状态机合法性校验。

（3）设备采购管理模块（M3）：包含教师与实验员新设备申购单提报、预算总价自动核算、管理员采购合规审批（批准/驳回）、防重复审批控制，以及到货验收后按申购数量自动批量创建 IN_STOCK 设备台账。

（4）设备使用管理模块（M4）：包含在库设备借用申请与审批、借出状态自动切换、应还日期校验、设备归还完好性验收（完好归还自动恢复 IN_STOCK，受损归还自动触发转修联动并生成维修工单）以及超期未还记录动态检测。

（5）维修与报废管理模块（M5）：包含在库或借出设备故障报修登记、待处理维修工单派工、维修完工验收恢复在库、老旧损坏设备报废申报与审批、未结案维修单自动同步结案，以及 SCRAPPED 报废终态不可逆锁定。

（6）仓库库存管理模块（M6）：包含全院实验室设备库存总台数、各状态（在库、借出、维修、报废）分类计数、实验室固定资产总值精确汇总，以及设备完好率（$(\text{在库数}+\text{借出正常数})/\text{总台数}\times 100\%$）动态盘点计算。

（7）物资与耗材管理模块（M7）：包含低值易耗品与危化试剂分类建档、危化品标识、耗材补充入库累加、领用出库防超领校验，以及当前库存低于安全阈值（currentStock < safetyThreshold）时的自动低水位预警。

系统边界之外（不包含）的内容界定：① 本系统仅负责实验室内部的采购申请预算核算、审批与到货验收入账，不直接对接学校财务处银校直联资金拨付系统与政府采购招投标外网平台；② 本系统管理设备的台账状态与维保履历，不包含示波器等仪器底层硬件 USB/串口实时实验波形数据的采集与分析；③ 不包含跨校区大型货运车辆的外部物流轨迹追踪。

3. 风险评估和规避

3.1 技术风险与规避方案

（1）设备多状态非法跃迁与业务规则冲突风险：实验设备在借用、归还、报修、维修、报废之间存在复杂的网状流转关系，若仅靠外层业务方法零散判断状态，极易出现“已借出设备未归还即被报废”或“已报废设备被重新借出”的严重逻辑漏洞。规避方案：在领域层设计内聚的有限状态机枚举 EquipmentStatus，通过 canTransitionTo(target) 集中封装状态转移矩阵，并在 EquipmentService.transitionStatus() 中强制执行前置守卫校验，任何非法状态迁移立即抛出 IllegalStateException 阻断事务。

（2）跨模块级联操作的数据一致性风险：采购单到货批量入库（M3 联动 M2）、设备受损归还自动转修（M4 联动 M2 与 M5）、设备报废自动结案未完成维修单（M5 内部联动）均涉及多实体协同更新。规避方案：引入统一业务门面控制器 LabSystemFacade 编排跨服务调用，在业务层先执行角色权限校验、日期边界校验与状态机预检，校验全部通过后再顺序更新主从表并追加不可篡改的安全审计日志。

3.2 管理风险与规避方案

（1）需求范围蔓延（Scope Creep）导致进度延期风险：在原型评审阶段可能不断涌现诸如硬件联网控制、移动端小程序等附加想法，威胁核心排期。规避方案：在里程碑 M2 冻结《需求分析规格说明书》与七大核心模块基线，建立严格的需求变更控制流程（CCB 评审），非核心扩展需求一律归入后续迭代待办列表（Backlog）。

（2）团队成员多门专业课并行导致沟通与集成滞后风险：大三上学期专业课程与实验任务密集，成员开发时间碎片化。规避方案：采用清晰的五层分包接口契约，提前锁定各 Service 方法签名；建立每周两次例会同步机制与 Git 小步提交规范，每完成一个子模块立即运行 run-tests.ps1 自动化回归脚本。

3.3 其他风险与规避方案

除技术与管理风险外，项目还面临跨机器环境运行兼容性风险及答辩现场演示突发故障风险。项目组制定了全周期风险评估与应对策略矩阵，如表 3-1 所示。

表 3-1 项目风险评估与应对策略矩阵表
